# Ember Knight 🔥⚔️

A complete 2D side-scrolling jumping game for the browser — **HTML5 canvas, vanilla
JavaScript modules, zero dependencies, zero build step**.

Every sprite in the game is generated by the Python scripts in `tools/`, so the whole
project is code: the hero's sprite sheet (idle / run / jump / fall / attack / hurt /
land / death), two enemies, all the tiles, props, pickups and both parallax
background layers are drawn pixel-by-pixel at build time and packed into
`sheet.png` + `sheet.json` atlases.

```
 ├── index.html          page shell: canvas, loading bar, touch controls
 ├── assets/             generated sprite sheets + atlases + backdrops
 ├── src/
 │   ├── game.js         loop, states, camera, HUD, 3x5 pixel font
 │   ├── entities.js     hero physics, AI, pickups, particles
 │   ├── levels.js       level data, tilemap, baked terrain, parallax
 │   ├── loader.js       atlas loading + animation
 │   ├── input.js        keyboard, touch buttons, pause/menu keys
 │   └── audio.js        runtime chiptune SFX + looping music
 └── tools/
     ├── pixel.py        tiny pixel-art drawing toolkit
     ├── generate_hero.py    the player character, all 8 animations
     ├── generate_enemy.py   slime + bat sheets
     ├── generate_world.py   tiles, props, backgrounds
     ├── serve.mjs       zero-dependency static server
     ├── headless.mjs    runs the game in Node and records draw calls
     └── replay.py       renders those recordings to PNG (visual regression)
```

## Play it

```bash
node tools/serve.mjs          # → http://localhost:8080
```

(Or `npm start`. ES modules + `fetch()` need an http origin, so open it through the
server rather than double-clicking `index.html`.)

## Game features

* **8 hero animations** driven by a small state machine (idle, run, jump, fall,
  attack, hurt, land, death) with input buffering, coyote time, variable jump
  height and a double jump.
* **Sword combat** with an active-hit window that matches the sprite's slash
  frames, plus a crescent motion arc, hit sparks and screen shake.
* **Enemies with distinct AI** — slimes that hop at you and bite, bats that hover
  on a sine wave and dive-bomb; both can be stomped or cut down.
* **3 levels** (Sunlit Meadows → The Old Quarry → Skyward Ruins) with coins,
  hearts, potions, spikes, pits, one-way platforms and a goal banner.
* **Juice** — hit-stop, screen shake, dust, sparks, coin pops, flashes,
  parallax sky/hills/treeline, chiptune music and SFX synthesized in WebAudio.
* **Pixel-perfect** 320×180 internal resolution, integer-scaled to any screen;
  keyboard + touch controls; high score and progress in `localStorage`.

## Regenerating the art

```bash
python3 -m pip install Pillow           # the only requirement
npm run art                             # rewrites every PNG/JSON in assets/
```

Each generator also has a preview mode so you can eyeball a sheet while you
tweak poses:

```bash
python3 tools/generate_hero.py --preview /tmp/hero.png    # contact sheet
python3 tools/generate_hero.py --strip run                # one animation, huge
python3 tools/generate_enemy.py --preview /tmp/enemy.png
python3 tools/generate_world.py --preview /tmp/world.png
```

## Testing without a browser

`tools/headless.mjs` boots the real game inside Node against a fake DOM whose
canvas 2D context *records* every draw call, then `tools/replay.py` turns those
recordings into PNGs — so gameplay logic and visuals can be checked from a
terminal (this is how the game was developed and verified):

```bash
node tools/headless.mjs --seconds 60 --shot 20,40 --out /tmp/frames   # play a level
node tools/headless.mjs --measure                                     # jump arc tuning
node tools/headless.mjs --noenemies --god --tracehero 4,4.5            # walk-through
python3 tools/replay.py /tmp/frames/shot20.json --zoom 3               # → PNG
```

Useful flags: `--level N`, `--bot 0` (stand still), `--goto <tile>` (teleport),
`--killat <sec>`, `--noenemies`, `--god`, `--debug`.

## Level editing

Levels live in `src/levels.js` as plain data — ground spans, platforms, blocks,
spikes, coins, enemies, props and the goal tile:

```js
ground:    [[0, 24], [28, 49], [53, 79]],
platforms: [{ x: 12, y: 10, w: 4 }],
blocks:    [{ x: 40, y: 11, w: 2, h: 2, kind: 'stone' }],
spikes:    [{ x: 60, w: 3 }],
coins:     [row(12, 8, 4), arc(22, 11, 4)],
enemies:   [{ type: 'slime', x: 34 }, { type: 'bat', x: 62, y: 8 }],
```

Spikes automatically sit on top of whatever terrain is beneath them, and the
whole tile grid plus props are pre-rendered once into an offscreen canvas at
level start, so rendering a level costs a single `drawImage`.

Useful numbers if you tune the physics: a running jump clears **5.4 tiles** and
rises **4.2 tiles**; a double jump clears **8 tiles** and rises **7.3**.
